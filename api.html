The transit API.

This is the live data feed behind the academy’s Live Transit map and the bus count on the Forge Line page: real-time Detroit Department of Transportation (DDOT) bus positions, served as JSON through the academy’s proxy. No key required.

Base URL: https://forge-line-live-proxy.netlify.app

Endpoint

GET /api/vehicles
Parameters
None.
Refresh
The feed updates roughly every 60 seconds; the proxy caches upstream responses for 60 seconds.
CORS
CORS-enabled for web use — call it directly from browser JavaScript.
Auth
None. The DDOT key lives server-side in the proxy and is never exposed.

Top-level fields

FieldTypeDescription
generated_atstringISO 8601 UTC timestamp of when the proxy built this response.
countintegerNumber of vehicle objects in vehicles.
vehiclesarrayLive vehicle snapshots (fields below).
sourcesobjectPer-agency feed status: ok, at, and either vehicles or a reason.
stalebooleanPresent and true only when the upstream feed was unreachable and the proxy served its last cached snapshot. Treat positions as older than generated_at suggests.

Vehicle fields

FieldTypeDescription
agencystringddot today; smart when that feed comes online.
route_idstringGTFS route id. Currently 1 (Vernor), 4 (Woodward), 10 (Greenfield), 16 (Dexter).
vehicle_idstringAgency vehicle number.
lat / lonnumberWGS84 position in decimal degrees.
bearingnumberCompass heading in degrees. Omitted when unknown.
speed_mphnumberReported speed in miles per hour. Omitted when unknown.
updated_atstringVehicle timestamp as reported by the agency feed. Omitted when unknown.

Rate-limit etiquette

  • Poll at most once per 30 seconds. The academy’s own map polls every 60 seconds — matching that is plenty.
  • Polling faster than the ~60-second feed refresh returns the same cached snapshot; use generated_at to detect genuinely new data instead of re-polling.
  • Cache responses client-side. Don’t fan out one page view into many parallel requests.
  • Never try to bypass the proxy or extract the agency key — the key stays server-side by design.

Building a student project or a community tool? The 60-second cadence is the intended use. If you need something the API doesn’t offer, the logged history below may already have it.

Logged history dataset

Every 5 minutes, a scheduled job polls this API and appends the snapshot to a public log — the raw material for headway analysis, reliability scores, and arrival predictions. Vehicle objects in the log use exactly the same field names as the live endpoint above, so code written against the live feed reads the history without translation.

  • Repository: github.com/smit4786/forge-line-transit-data
  • Format: forge-line.telemetry/v1, documented in the repo’s SCHEMA.md
  • Day index: https://raw.githubusercontent.com/smit4786/forge-line-transit-data/main/data/index.json
  • One day of polls: https://raw.githubusercontent.com/smit4786/forge-line-transit-data/main/data/2026-10-03.jsonl (replace the date)

Failed polls are never logged as empty records — a gap in a day’s file means that poll failed, not that zero buses were running.

Error behavior

  • HTTP 200 with "stale": true — the agency feed was unreachable; the proxy served its last cached snapshot. Keep displaying it, but mark the data as older, and keep retrying on your normal cadence.
  • Non-200 or network failure — back off and retry after 60 seconds. Don’t hammer the endpoint; the feed only refreshes about once a minute anyway.
  • Empty vehicles array — valid response, no buses currently reporting on the covered routes (common late at night).

All timestamps are UTC. Route coverage may expand as feeds are added; check sources to see which agencies are live.
