Live Transit Detroit · Releases

Release Record

Live Transit builds carry a build stamp — the build identifier. Releases carry a public dot name over the stamp, so a rider, a partner, or a reporter can cite a release by a name, not a timestamp. A dot is assigned when its payload has passed the release gate: verified payloads, browser-checked on the production site, with a one-step rollback per dot. Dots ship per-feature — when the payload verifies, not on a fixed calendar.

Live Transit v2.0 — a new planning engine

Released October 21, 2026 · Build 20261021-0917

The trip planner now runs on Live Transit's second-generation engine. The answers are the ones riders already get — verified identical on our regression grid — and they arrive faster: the median plan time on the Woodward acceptance trip is down from 340 ms to 267 ms in benchmark measurement.

The new engine also computes fewest-transfer and least-walking alternatives, departure windows, and arrive-by plans; those reach the planner's interface in a following release (v2.1). DDOT and SMART trips are planned from the agencies' published schedules; live bus positions stay on the map, as before. Planning still runs entirely on the rider's device — an origin and a destination never leave the phone.

Payload: the assembled second-generation planner engine (one file, byte-verified against its benchmark record before release). Rollback unit: build 20261020-1647.

The v1 line

Builds before the dot era belong to the v1 line and carry build stamps only — no retroactive dot numbers are assigned. The last v1 build was 20261020-1647.
